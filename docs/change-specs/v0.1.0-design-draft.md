# Test and Practice Studio v0.1.0 — design draft

Status: proposed implementation scope for review. Naming and repository separation are owner-confirmed; unselected defaults are proposals.

## Proposed first increment
1. Import GradeCam XLSX using header detection and standard-code columns, excluding preamble and performance-band legend.
2. Review source-standard to canonical-skill mapping using the actual custom map. Report unmapped or unsupported outcomes.
3. Offer manual standard selection and teacher-adjustable targeting by reported performance. Preserve missing evidence as its own state; no automatic mastery claim.
4. Select item count, seed and supported generation options. Call a pinned Math Engine version.
5. Preview questions and corresponding keys before export. Finalize Word/PDF templates, headers, footers, column and divider choices before implementation.

## Architecture boundary
Studio owns importing, local learner references, targeting, document composition and output. Engine owns mathematical generation and answers. Pass curriculum/skill IDs and generation options to the engine, not student identities. Pin engine and mapping versions in generated-work metadata.

## Acceptance plan
Synthetic import fixtures reproduce the attached export structure. Verify header detection, 0 versus missing, percentage scaling, duplicate/unknown headers, malformed cells and legend exclusion. Validate student targeting, supported-skill boundaries, deterministic generation, question/key agreement and batch separation. Render exported pages to inspect fractions, exponents, negative signs, units, diagrams, clipping and page breaks. Test storage/deletion if persistence is included. Hosted testing follows an explicit deployment decision.

## Outstanding design choices
First-release skill coverage; targeting threshold/default allocation; exact print template; output formats in the first increment; local persistence; supported browsers; deployment method. These choices are not silently approved by this draft.
